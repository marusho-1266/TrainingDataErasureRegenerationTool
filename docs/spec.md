# Flutterネイティブアプリ仕様書：学習用書き込み消去ツール

## 1. プロジェクト概要

- **目的**: スマホのカメラで撮影した書き込み済みの問題集から、手書き回答を AI で消去し、真っ新な状態に近づけて「解き直し」を支援する。完全復元や高精細な原本再現は保証せず、**印刷後に問題文・選択肢・図表の主要情報が読めること**を MVP の実用基準とする。
- **ターゲット**: 自己学習のために中古教材や一度解いたドリルをリセットしたいユーザー。
- **設計思想**: **完全ローカル処理（オンデバイス AI）**。画像を**外部サーバーへ一切送信せず**、プライバシーと著作権リスクを回避する。教材の再利用・複製については**ユーザー自身の権利範囲内での利用**とし、アプリ側は処理手段のみを提供する（法的文言は製品公開時に別途検討）。

## 2. 技術スタック（スマホネイティブ推奨）

| 領域 | 採用 | 理由 |
|------|------|------|
| **Framework** | Flutter（iOS / Android） | 単一コードベースで両 OS をカバーする。 |
| **Document Scan** | [google_mlkit_document_scanner](https://pub.dev/packages/google_mlkit_document_scanner) | ドキュメント検出・歪み補正が一パッケージで完結し、撮影〜補正の UX を素早く実現できる。 |
| **AI Inference** | [onnxruntime_flutter](https://pub.dev/packages/onnxruntime_flutter) | 端末の CPU / GPU / NPU を利用したオンデバイス推論。 |
| **Image Processing** | `image`（Dart パッケージ）または `opencv_dart` | AI 入力の整形、マスク画像の作成、前後処理。必要に応じて OpenCV 相当の処理は `opencv_dart` を検討。 |
| **出力** | PDF | 処理後画像を PDF 化し、共有・印刷（AirPrint、ファイルアプリ、Google ドライブ等）へ渡す。 |

- **モデル**: スマホ実運用を前提に、**量子化済み LaMa 等の inpainting 用 ONNX** を採用する。入力解像度・メモリ・推論時間のトレードオフで選定し、**ライセンス・配布可能な重み**を満たすこと。
- **モデル配信**: アプリサイズとの兼ね合いで、**アセット同梱**または**初回オンデマンド取得（同一アプリの配信元に限定）**のいずれかを採用する。取得する場合も**画像データは送信しない**。取得物はオンデバイスにキャッシュする。

## 3. 主要機能と UX フロー

### ① 撮影・スキャン（Google ML Kit Document Scanner）

- **UX**: アプリ内でスキャナを起動すると、問題集の四隅などを自動検出し、**青い枠**などガイドが表示される。シャッター後、**台形補正・クロップ・高画質化（白黒強調など）**までパイプライン化された画像が得られる。
- **補足**: 検出失敗や極端な歪みの場合は、後続フェーズで**手動四隅調整**を検討する（MVP はスキャナの標準動作を主導線とする）。

### ② AI 消去処理（オンデバイス）

- **UX**: スキャン完了後、**処理中インジケータ（アニメーション等）**を表示し、数秒〜数十秒後（端末依存）に書き込みが消えた画像を表示する。
- **技術**:
  - `onnxruntime_flutter` で LaMa（スマホ向け量子化 ONNX 等）をロード。
  - 正規化・リサイズ・マスク生成など前処理を Dart / `image` / `opencv_dart` で行い、inpainting で**ペン・鉛筆跡の消去と背景補完**を行う。
- **マスク（MVP の現実的な範囲）**:
  - **手動**: ブラシで塗る / 消す（精緻な調整用に推奨）。
  - **自動（ヒューリスティック）**: 色域しきい値＋モルフォロジーで「赤・青・鉛筆っぽい灰」等の候補をマスク。**深層セグメンテーションは MVP 外**とし、誤検出時は手動で補正できること。
- **消去強度**: モデルがパラメータを持たない場合は、マスクの膨張・ぼかしや元画像とのブレンドなど**前後処理で定義**し、UI ラベルと実装を一致させる。

### ③ 保存・活用（ローカル）

- **UX**: 処理後画像をアプリ内**ライブラリ**に保存。必要に応じて **PDF 化**し、OS の共有シート（AirPrint、クラウド、他アプリ）へ渡す。
- **品質目標**: MVP は**判読性**を合格基準とし、原本同等の解像度や厳密な紙面寸法の再現は求めない。

## 4. 画面設計案（Mobile First）

### ホーム画面

- 中央に **「新しいページを撮影」** を主ボタンとして配置。
- 下部に **過去のスキャン履歴**（ライブラリへの短縮リストまたはサムネイル列）。

### カメラ / スキャン画面

- ML Kit による**リアルタイムのスキャン枠表示**（仕様に準拠したガイド UI）。

### プレビュー・編集画面

- **Before / After** の切り替え（トグルまたはスライダー比較）。
- **（オプション）** 鉛筆専用・赤ペン専用など、消す対象を選ぶフィルターボタン（自動マスクプリセットと対応）。
- 四隅補正・マスク編集が必要な場合はモード切替で提供する。

### ライブラリ画面

- 保存画像を**サムネイル**表示。
- **複数選択**して一括 PDF 化。単一画像の PDF 出力も可能とする。

## 5. 実装ステップ（現実順）

1. **Step 1**: Flutter プロジェクト基盤、`google_mlkit_document_scanner` の統合、カメラ権限・エラーハンドリング。
2. **Step 2**: スキャン結果のプレビュー画面、ギャラリー保存（ローカル DB またはファイル＋メタデータ）。
3. **Step 3**: `onnxruntime_flutter` の統合、ONNX のロード（同梱または初回取得）、入力テンソル形状・前後処理のパイプライン確立（ダミー推論から差し替え可）。
4. **Step 4**: 色域＋モルフォロジーによるオートマスク（プリセット）、手動ブラシ、消去強度 UI。
5. **Step 5**: PDF 生成（例: `printing` / `pdf` パッケージ等、選定は実装時にライセンス・品質で確定）、共有シート連携。
6. **Step 6**: ライブラリの一覧・複数選択・一括 PDF。

## 6. 非機能要件・制約

- **データの秘匿性**: 画像、マスク、出力 PDF、ファイル名、EXIF は**端末内**で扱い、**自前サーバーや第三者解析へ画像を送信しない**。計測が必要な場合も、個人を特定し得る画像ピクセルや本文 OCR 結果を含めない。
- **オフライン**: モデルを同梱できれば**初回からオフライン利用可能**。モデルを後から取得する方式の場合のみ、初回ダウンロード時にネットワークが必要とする。
- **パフォーマンス**: 端末差が大きいため、**進捗表示・キャンセル（可能なら）・推奨環境・処理時間の目安**を UI に明示する。長辺解像度の上限は実機計測で決定する（例: 768〜1024 px 前後を初期候補とし、`onnxruntime` の実行プロバイダ設定と合わせて調整）。
- **プラットフォーム**: MVP は **iOS・Android の最新 OS 世代を主ターゲット**とし、ML Kit・ONNX ランタイムの対応矩阵に合わせて最小バージョンを定める。

## 7. 既知の限界（仕様に含めておく）

- 消しゴムかすれ、蛍光ペン、薄い鉛筆と淡い印刷のコントラスト不足は**自動では困難**な場合がある。
- 図表の細線がマスクに巻き込まれると inpainting でにじむため、**手動マスクの修正が前提**となることがある。
- モデル・解像度・量子化により**細字の再現**に限界がある。
- 問題文の色と手書き色が似ると、ヒューリスティック自動マスクは**誤検出**しやすい。
