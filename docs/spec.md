# Flutterネイティブアプリ仕様書：学習用書き込み消去ツール

## 1. プロジェクト概要

- **目的**: スマホのカメラで撮影した書き込み済みの問題集から、手書き回答を AI で消去し、真っ新な状態に近づけて「解き直し」を支援する。完全復元や高精細な原本再現は保証せず、**印刷後に問題文・選択肢・図表の主要情報が読めること**を MVP の実用基準とする（具体は §2）。
- **ターゲット**: 自己学習のために中古教材や一度解いたドリルをリセットしたいユーザー。
- **設計思想**: **完全ローカル処理（オンデバイス AI）**。**ユーザーの教材画像・マスク・生成 PDF・ファイル名・OCR 相当のテキストは外部サーバーへ送信しない**。プライバシーと著作権リスクを抑える。教材の再利用・複製については**ユーザー自身の権利範囲内での利用**とし、アプリは処理手段のみを提供する。**モデルファイルの初回取得**や**匿名クラッシュログ**等の境界は §11 および §14 で扱う。

## 2. MVP 受け入れ基準（テスト可能な定義）

以下を満たすこと。数値・端末は PoC 後に確定し、本節を更新する（未確定箇所は §15）。

### 2.1 品質（判読性）

- **代表サンプル**: 社内合意の**サンプル画像セット**（例: A4 印刷の問題集を想定した N 枚。手書きの色・濃さが異なるケースを含む）を用意し、リリース判定に用いる。セットの枚数・取得方法は未決（§15）。
- **撮影・解像度条件（案）**: A4 1 ページを**おおむね 300 dpi 相当**の解像度でスキャンした入力を基準とする（長辺ピクセル数は PoC で「合格ライン」として確定）。
- **合格の定義（案）**: 上記サンプルを規定条件で処理し、**処理後の PDF を A4 に印刷**したとき、**本文でおおよそ 8 pt 相当以上**の印字が**目視で連続して読める**こと。図表の細線・脚注は「読めれば良い」に含め、完全復元は求めない。
- **合格率（案）**: 代表セットの **◯% 以上**で上記を満たすこと（◯ はプロダクトオーナーと合意）。残りは「既知の限界」または手動マスク・再撮影で改善可能とする。
- **評価の運用（再現性）**: 「目視で連続して読める」の判定ぶれを抑えるため、(a) **裁定役を明確にする**（プロダクトオーナー単独、または QA オーナー＋レビュア 2 名の合議など、いずれかを採用し手順書に書く）、(b) **照明環境を固定または記録する**（再評価可能な屋内・時間帯。必要なら照度計で数値も §15 で確定）、(c) **印刷は規定機種／プリンタ 1 台**（または社内許可リスト載せのモデル）に限定する。プリンタ・用紙ロットまたは §2.1 の条件を変更したときは代表セットでの**差分再評価**を検討する。

### 2.2 プロダクト受け入れ（機能・非送信）

- スキャン後の**補正画像**を、ライブラリ保存または推論実行の前に、ユーザーが**必ず確認**できる。
- **処理前**と**処理後**の画像を**同一画面で比較**できる（トグルまたはスライダー等）。
- 自動マスクが不十分な場合、ユーザーが**手動でマスクを追加・削除**できる。
- 推論中は**進捗または処理中状態**を表示し、**可能な範囲でキャンセル**できる（キャンセル時は途中結果を破棄し、元画像は保持）。
- **画像・マスク・PDF 本文相当のバイナリ・ファイル名・OCR 相当データ**を**自前または第三者の解析サーバーへ送信しない**（モデル配信 URL への GET のみは §11）。
- モデルを**初回ダウンロード**する方式の場合、送信ペイロードは**モデルファイル取得に必要な範囲に限定**し、**画像データは送らない**。
- PDF 出力後、**OS 標準の共有シート**から印刷またはファイル保存に進める。
- 処理結果が低品質でも、**元の補正済み画像を破棄せず**、マスク変更・再推論など**再編集の起点**にできる。

## 3. PoC ゲート条件と未達時の方針

### 3.1 ゲート条件（案・要実機での閾値確定）

次を**inpainting を含む端到端**で満たすことを、本モデル・アーキテクチャでの実装 GO とする。

| 項目 | 条件（初期案） |
|------|----------------|
| 入力 | 長辺 **1024 px**（仮）、**手動マスク済み**の画像 **1 枚** |
| 対象端末 | MVP で掲げる**最小スペック端末**（§15 で機種/OS を確定） |
| 推論時間 | 上記端末で**ワンショット推論が 30 秒以内**（目安・PoC で調整） |
| 安定性 | 処理中に**アプリがクラッシュしない** |
| メモリ | **ピークメモリが端末許容範囲内**（具体的な上限 MB は PoC 計測で定義） |
| 実行プロバイダ | iOS / Android で**利用可能な ONNX Runtime の Execution Provider** を明示し、落ちない組み合わせを記録 |

### 3.2 未達時の方針（例）

- 長辺の**上限を下げる**（例: 768 px）、**量子化強度・モデル差し替え**、**タイル分割推論**（実装コスト許容時）を検討する。
- いずれも厳しい場合は、**対象端末の floor を上げる**、または **MVP 機能を限定**する（仕様変更として記録）。

## 5. 主要機能と UX フロー

### ① 撮影・スキャン（Google ML Kit Document Scanner）

- **UX**: アプリ内でスキャナを起動すると、問題集の四隅などを自動検出し、**青い枠**などガイドが表示される。シャッター後、**台形補正・クロップ・高画質化（白黒強調など）**までパイプライン化された画像が得られる。
- **補足**: 検出失敗や極端な歪みの場合は、後続フェーズで**手動四隅調整**を検討する（MVP はスキャナの標準動作を主導線とする）。失敗時は §7 を参照。

### ② AI 消去処理（オンデバイス）

- **UX**: スキャン完了後、**処理中インジケータ**を表示し、推論完了後に結果を表示する。
- **技術**: `onnxruntime_flutter` で ONNX をロード。正規化・リサイズ・マスク生成を Dart / `image` / `opencv_dart` で行い inpainting する。
- **マスク**:
  - **手動**: ブラシで塗る / 消す（§6・§8）。
  - **自動（ヒューリスティック）**: 色域しきい値＋モルフォロジー。**深層セグメンテーションは MVP 外**。
- **消去強度**: モデルがパラメータを持たない場合は、マスクの膨張・ぼかしや元画像とのブレンド等で定義し、**UI ラベルと実装を一致**させる。

### ③ 保存・活用（ローカル）

- **UX**: 処理後画像をアプリ内**ライブラリ**に保存。必要に応じて **PDF 化**し、OS の共有シートへ渡す。品質・PDF 詳細は §2・§10。

## 6. 画面設計案（Mobile First）

### ホーム画面

- 中央に **「新しいページを撮影」** を主ボタンとして配置。
- 下部に **過去のスキャン履歴**（ライブラリへの短縮リストまたはサムネイル列）。

### カメラ / スキャン画面

- ML Kit による**リアルタイムのスキャン枠表示**。

### プレビュー・編集画面

- **Before / After** の切り替え（またはスライダー比較）。**同一画面内で比較可能**とする（§2.2）。
- **（オプション）** 鉛筆専用・赤ペン専用など、自動マスクのプリセットボタン。
- マスク編集モードでは**マスクの可視化**（例: 色オーバーレイ）を表示する。
- 四隅補正は MVP 外の可能性があるが、入れる場合はモード切替で提供する。

### ライブラリ画面

- 保存画像を**サムネイル**表示。**複数選択**して一括 PDF 化。単一画像の PDF も可。ページ順序は §10.1。

## 7. 失敗時・低品質時の UX

| 状況 | ユーザーへの表示（例） | 推奨導線 |
|------|-------------------------|----------|
| ドキュメント検出失敗・スキャン取消 | 理由の簡潔な説明 | **再撮影**、問題が続く場合は別環境・光量のヒント |
| モデルロード失敗・破損 | 再試行または再取得の案内 | **再ダウンロード**（該当時）、**同梱モデル**の検証、改善できない場合はサポートまたは FAQ へ |
| 推論タイムアウト / 極端に遅い | 時間がかかっていること、キャンセル可 | **キャンセル**、**解像度を下げて再実行**（提供する場合）、対象端末の注意表示 |
| 推論中クラッシュ（再起動後） | — | 直前の**元画像の保持**を試みる（実装可能な範囲）、再編集可能にする |
| 結果が判読できない | 既知の限界に触れる旨 | **マスク修正**、**消去強度変更**、**再撮影**、**解像度変更**（提供する場合） |
| 自動マスクが本文を巻き込む | 手動修正の推奨 | **マスク削除ブラシ**、**Undo**、**Before 確認** |
| ストレージ不足 | 保存失敗の明示 | **古いスキャンの削除**（§9）、端末の空き容量案内 |

## 8. 手動マスク編集（MVP 範囲）

自動マスクの誤検出が前提のため、以下を **MVP に含める**。

- **マスク追加**（ブラシ）
- **マスク削除**（消しゴムまたは同相当）
- **ブラシサイズの変更**
- **ピンチズーム**（細部編集のため）
- **Undo**（少なくとも 1 ステップ以上、実装はスタック深度を仕様で定める）
- **マスクの可視化**（オーバーレイ表示の ON が基本）

**MVP に含めない（または任意）**: **Redo**（あれば望ましいが、未実装でも MVP は成立とする）、**多段 Undo の深さ**は実装コストに応じ最小限から開始し、PoC 後に拡張可能とする。

## 9. ローカルライブラリとデータ保持

| データ | 内容例 | 保存先の方針 | 削除 |
|--------|--------|--------------|------|
| 元画像（補正後） | スキャン直後のラスタ | アプリサンドボックス内（具体的パスは実装で定義） | ユーザーがライブラリから削除可能 |
| マスク | 最後に確定したマスク | 同一エントリに紐づけて保存 | 画像削除時に連動削除 |
| 結果画像 | inpainting 出力 | 任意で保存（再編集の起点として元画像を残す方針は §2.2） | 同上 |
| PDF | エクスポート用 | 共有時に生成、またはキャッシュ（要否は未決） | ユーザー操作で削除 |
| メタデータ | 作成日時、サムネイルパス等 | ローカル DB 等 | アプリのアンインストールで消去 |

- **暗号化**: **TBD**（端末ファイルシステムの保護に任せる / SQLCipher 等は §15）。
- **バックアップ**: iCloud / Google バックアップに**教材画像が含まれるか**は OS 設定に依存する。**含めたくない場合のオプション**（オンデバイス限定フラグ等）は未決。
- **EXIF**: 保存時に**除去するか保持するか**は未決。プライバシー優先なら**除去をデフォルト**とする案。
- **アプリ削除**: OS 標準どおりサンドボックス削除。**ユーザーデータのエクスポート**は MVP 外でも可。

## 10. PDF 出力仕様（MVP）

### 10.1 ページと順序

- **単一画像**: 1 ページの PDF。
- **複数画像**: ユーザーがライブラリで選択した**順序**をページ順とする。

### 10.2 用紙・スケール

- **用紙サイズ**: **A4** を既定とする（他サイズは後続）。
- **スケール**: 画像をページ内に**フィット**（余白は均等か片寄りは実装で定義）。**厳密な印刷物の寸法再現は求めない**。

### 10.3 余白・画質

- **余白**: 既定 **10〜16 mm 程度**（印刷機差を吸収、正確値は実装時に固定）。
- **ラスタの再圧縮**: 例として **JPEG 品質 85〜92** 程度を初期値とし、ファイルサイズと判読性のバランスを PoC で調整。

### 10.4 ファイル名

- 共有時: `Scan_YYYYMMDD_HHmmss.pdf` のような**汎用プレフィックス**（ユーザー名・教材名を推測される文字列は含めない）。複数ページ時は `Scan_YYYYMMDD_HHmmss_part.pdf` 等、衝突回避ルールを定義する。

## 11. 通信・ログ・「完全ローカル」との境界

### 11.1 送信しない（原則禁止）

- 教材**画像**、**マスク**、**PDF バイナリ**、**ファイル名**、**OCR 結果**、ユーザーが入力した**注釈テキスト**。

### 11.2 送信し得るもの（採用時のみ・PoL と整合）

- **モデルファイル**の HTTPS 取得（URL・ホストはアプリ提供元が管理）。**リクエストに画像を含めない**。
- **匿名化されたクラッシュレポート**（スタックトレース、機種、OS バージョン等）を用いる場合:**画像・ファイル名・パスを含めない**ことを受け入れ条件とする。
- **利用計測**を行う場合: **イベント名・集計のみ**とし、画像関連ペイロードを送らない。

**計測・クラッシュ送信の採用可否**は §15。未採用なら本節の「送信し得るもの」はモデル取得のみとする。

### 11.3 モデル配信インフラと接続メタデータ（外向け説明）

- アプリから **HTTPS でモデルを取得**する際、CDN / アプリ側サーバーの都合で一般的に **送信元 IP アドレス、User-Agent、リクエスト時刻など** がアクセスログ等に記録され得る。画像・ファイル名・ユーザー ID をペイロードに載せなくても、**インフラ提供者のログに接続メタデータが残る**可能性がある。プライバシーポリシーではこれを過不足なく説明する（§14）。

## 13. 非機能要件・制約

- **オフライン**: モデル同梱なら初回からオフライン可。初回 DL 方式は初回のみネットワーク必須。
- **パフォーマンス UI**: 進捗、推奨環境、目安時間、可能ならキャンセル（§2.2）。
- **プラットフォーム**: MVP の**最小 OS・端末**は PoC 後に `spec.md` に明記する（§15）。

- PDF の**余白 mm**・**JPEG 品質**の最終値
- **計測・クラッシュログ**の採用可否とベンダー
- 代表**サンプル画像セット**の枚数・合格**率**
- 利用規約・プライバシーポリシー・著作権表示の**最終文案**

## 16. Document Scanner・観測系 SDK の確認項目（実装前チェックリスト）

### Document Scanner（ML Kit）

- iOS / Android それぞれの**最小 OS**とパッケージ README の一致
- **Google Play 開発者サービス**等の依存の有無（Android）
- 必要**権限**（カメラ、ストレージ相当）とストア審査での説明文案
- **オフライン**でスキャン UI が利用可能か（ML Kit の制約に照合）
- **商用利用**・再配布に関する Google ML Kit の条件
- UI **カスタマイズ**の許容範囲（枠色・文言）
- 失敗時の API 挙動と §7 の整合

### 計測・クラッシュ送信を採用する場合（§15 で GO のとき）

採否が **§15 で未決のうちは本節の実装チェックリストをスキップしてよい**。採用する場合は**実装着手前**までに完了する。

- **採用 SDK**（例: Firebase Crashlytics、Sentry 等）ごとに、**既定で収集される項目**を公式ドキュメントで一覧化する（機種・OS、アプリ UUID、ユーザー識別子の有無、スタック、アプリ内状態のスクリーンショットの有無等）。
- **§11 の受け入れ条件**との整合: **画像・ファイル名・ローカルパス全文・OCR 結果**が送信経路に乗らないことを、設定・ラッピング・アノニマイザで明示的に確認する。
- SDK が **Advertising ID／設備固有 ID／インストール単位 ID** 等を送る場合、その扱いを **§14 のプライバシーポリシーおよびストア規約**と一致させる（オフにできるか、表示義務のみかを §15 で決定）。
- Breadcrumb やカスタムキー機能を使うときは **教材コンテンツ由来の文字列を載せない**ことをコードレビュー観点に含める。

## 17. 既知の限界（仕様に含めておく）

- 消しゴムかすれ、蛍光ペン、薄い鉛筆と淡い印刷のコントラスト不足は**自動では困難**な場合がある。
- 図表の細線がマスクに巻き込まれると inpainting でにじむため、**手動マスクの修正が前提**となることがある。
- モデル・解像度・量子化により**細字の再現**に限界がある。
- 問題文の色と手書き色が似ると、ヒューリスティック自動マスクは**誤検出**しやすい。
